SIR - Repair Shop Management System

A local-first web app that runs the entire operation of a TV repair shop: intake, quotes, payments, pickup, and customer notifications. It replaces a decades-old Visual FoxPro program with a self-hosted system running on a small PC inside the shop.

Python FastAPI React TypeScript SQLite Linux
working In development - already used daily at the shop.

The problem

For years, the shop managed every job with a Visual FoxPro program built decades ago. It still covered the basics, but it had no reliable data model, no traceability, and every change depended on knowledge that was disappearing. Data lived on a single machine and backups were manual.

Before writing a dedicated system, we evaluated a quick fix with the Google suite (Forms + Sheets + Apps Script). It did not solve the underlying problem: it added another kind of complexity, depended on an external account, and was a fragile patch.

The decision was to build a dedicated, self-hosted web app: business-owned data, a real relational model, and a tool designed around the shop's daily workflow.

The solution

SIR is a monolithic FastAPI app that serves both the API and the React SPA, running on a Xubuntu PC inside the shop and accessed over the local network from the counter PC and phones.

Intake & job lifecycle

Guided intake of customer and device, a state machine with contextual actions, and full history for every job.

Quotes & payments

Versioned quotes, deposits, partial payments, refunds, and a balance derived from approved quotes.

Parts & attachments

Special part orders that add their real cost, plus device photos and invoices attached to each job.

WhatsApp notifications

Templates and wa.me links to notify customers, with a log of sent messages and pickup reminders.

Reports

Monthly metrics with a yearly series and an insurance report generated as DOCX and PDF.

Local-first & backups

Works on the local network without internet, with local data and automatic backups.
